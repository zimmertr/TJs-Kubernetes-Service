## What this project is

TJ's Kubernetes Service (TKS) builds Talos Linux Kubernetes clusters on Proxmox VE with Terraform, using the `bpg/proxmox` and `siderolabs/talos` providers. It is open source and has users other than TJ. One Terraform root builds one cluster per workspace (TJ runs `stable` and `test` on the host `earth`). An optional `gpu_worker` module adds a Talos worker with a host GPU passed through. An optional `bootstrap/` root creates the Proxmox user Terraform runs as.

v2 is under construction. The pinned issue `[Epic] TKS v2 and the GPU worker` holds the PRD: a snapshot of intent at sign-off, not maintained afterwards. Its sub-issues `[T1]`–`[T32]` are the plan, tracked on the "TKS v2 + GPU" Project with "blocked by" relationships. The issues are the only living plan, so no plan or PRD files are committed. Work one task at a time, tick its checklist as subtasks land, and edit the issue when a task's scope changes.

## Decision records

Every design decision gets a record in `docs/decisions/`, written in the same PR as the change that makes the decision, as the project is built and as it evolves. Copy `0000-template.md` to the next free four-digit number, title it with the decision as one sentence, date every measurement, and add a row to the index in `docs/decisions/README.md`. A reversal is a new record that says `Supersedes NNNN`. The old record changes only its status line.

## Rules for every change

- **Never merge to `main` without TJ's approval.** Push branches and open PRs freely; TJ reviews in GitHub. Record: [0019](docs/decisions/0019-a-handful-of-prs.md)
- **Never run anything against real infrastructure without TJ's approval for that run.** That means `terraform apply` or `destroy`, `talosctl`, `kubectl`, SSH to a Proxmox host, or Proxmox API calls. Read-only commands included. Mocked tests and lint run freely.
- **Work in a clone under `/tmp`, not in TJ's checkout.** TJ runs several agents at once.
- **PR titles are conventional commits** (`feat:`, `fix:`, `docs:`, `ci:`, …; `!` for breaking). The squash commit title is the PR title, and it decides the release version. Record: [0013](docs/decisions/0013-ci-and-semver-releases.md)
- **Ship tests with behavior.** `terraform test` with `mock_provider` covers validation, resource counts and planned values. A behavior change without a test is incomplete.
- **TKS assumes a ready hypervisor.** It manages cluster-scoped Proxmox objects only: VMs, pools, image files, PCI mappings. Host settings (APT, IOMMU, ZFS and storage options, drivers) belong in Bootstrap-Proxmox or are done by hand. The one exception is the optional `bootstrap/` root for the Terraform user. Record: [0004](docs/decisions/0004-ready-hypervisor.md)
- **Optional features cost nothing when off.** A disabled feature plans zero resources, and a test proves it.
- **No hard-coded hardware addresses.** Devices are found through data sources (vendor and class), never by PCI address. Record: [0006](docs/decisions/0006-gpu-found-by-class.md)
- **A version bump never replaces a VM.** `talos_machine` upgrades the OS in place when the installer image changes, and `talos_cluster` upgrades Kubernetes. `talos_version` (installed OS, Renovate-managed) and `talos_config_version` (config contract, pinned at creation) are different things. Never lower the contract, because it regenerates the cluster's PKI. Record: [0011](docs/decisions/0011-in-place-upgrades-by-terraform.md)
- **No provisioners and no SSH.** Node removal is `talos_machine`'s `on_destroy` reset. Anything that would need SSH or root on the host (snippets, hookscripts) belongs outside TKS.
- **No backwards-compatibility code.** Use the provider's current resource names, and `proxmox_*` short names where they exist. Record: [0003](docs/decisions/0003-v2-breaking-rebuild.md)
- **Comments explain why, not what.**

## Development commands

Every CI check is a Make target that runs a pinned container image (`make fmt`, `make validate`, `make lint`, `make scan`, `make test`, `make actionlint`, `make docs`, and `make check` for all of them). The Makefile lands with task T5. Until then, there are no checks. `docs/CICD.md` describes the pipeline. Applies use `-parallelism=1` through `vars/config.env`, so upgrades roll one node at a time.
